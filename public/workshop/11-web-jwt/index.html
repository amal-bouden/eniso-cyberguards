🔑 The Secure Portal

Category: Web  |  Difficulty: Medium  |  Points: 250

📖 Description

A developer built an internal admin portal that uses JSON Web Tokens (JWTs) for access control. They thought that as long as there's a token, it must be valid — but they made a critical mistake in how they verify it.

You've been given a guest token. Your goal is to forge an admin token and get the portal to accept it.

The portal runs entirely in your browser. Use your browser's developer tools to inspect and manipulate the token.

💡 Hints

💡 Hint 1 — What's wrong with the token verification? (click to reveal)
Hint 1: JWT headers contain an "alg" field that tells the verifier which algorithm was used to sign the token. Some buggy implementations trust whatever algorithm the token itself claims — including "alg": "none", which means no signature at all. Try setting the algorithm to none!
💡 Hint 2 — How do I craft a JWT? (click to reveal)
Hint 2: A JWT is three base64url-encoded parts joined by dots: header.payload.signature. For alg:none, the signature is empty — just leave it blank after the last dot. You can encode the parts in your browser console:
btoa(JSON.stringify({"alg":"none","typ":"JWT"})).replace(/\+/g,'-').replace(/\//g,'_').replace(/=/g,'')
💡 Hint 3 — What payload do I need? (click to reveal)
Hint 3: The portal checks the role field in the token's payload. The guest token has "role": "user". Change it to "role": "admin". Keep the other fields (user, iat) the same.
💡 Hint 4 — Full forge-and-submit walkthrough (last resort!)
Hint 4: Run this in your browser console (F12 → Console):
function b64url(obj) { return btoa(JSON.stringify(obj)) .replace(/\+/g,'-').replace(/\//g,'_').replace(/=+$/,''); } const header = b64url({"alg":"none","typ":"JWT"}); const payload = b64url({"user":"guest","role":"admin","iat":1700000000}); const forged = header + '.' + payload + '.'; console.log(forged); // Paste the output into the token field and click Authenticate
